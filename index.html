01 · База

Что вообще происходит

Программист пишет код на понятном языке (C, C++, Rust, Go). Компилятор переводит его в машинный код: байты, которые процессор исполняет напрямую. Готовый файл называют бинарником.

Реверс — это обратный путь: из байтов восстановить, что программа делает. Полностью исходник не вернуть, часть информации теряется при компиляции. Нажми на этапы и посмотри, что исчезает.


    

    


    
Два подхода

    

      
Статический анализ
Читаем, не запуская

Открываем файл в дизассемблере/декомпиляторе (Ghidra, radare2), смотрим строки, функции, импорты. Безопасно: код не выполняется.

      
Динамический анализ
Запускаем и подглядываем
Отладчик (gdb, x64dbg), трассировка системных вызовов (strace), хуки (Frida). Видно реальные значения. Чужое и подозрительное запускай только в изоляции.

    


    
Словарик на 1 минуту

    

      
Регистр
Сверхбыстрая «переменная» внутри CPU: rax, x0, r0.

      
Стек
Память под локальные переменные и адреса возврата из функций.

      
Инструкция
Одна команда CPU: mov, add, cmp, jmp, call.

      
Секции
.text — код, .data — данные, .rodata — константы и строки.

      
Импорты
Чужие функции из библиотек (strcmp, printf). Сразу подсказывают, что делает программа.

      
Stripped
Бинарник без имён функций. Вместо check_password увидишь FUN_00101189.

💡
Язык тоже решает. C/C++/Rust/Go → машинный код (Ghidra). Java/Kotlin/C# → байткод, он декомпилируется почти до исходника (jadx, ILSpy). Python → .pyc, тоже свои декомпиляторы. Сначала определи, с чем имеешь дело.

  







  

    
02 · Архитектуры

    
Один код — разные процессоры

    

      
Архитектура (ISA) — это «язык» процессора. Один и тот же C-код превращается в разные инструкции. Ниже функция int add(int a, int b) { return a + b; } под пять архитектур.

    

    

    


    
Шпаргалка: куда смотреть

x86-64 (amd64)ПК, ноутбуки, серверыLinux: rdi rsi rdx rcx r8 r9
Windows: rcx rdx r8 r9		raxret

        
x86 (i386, 32-бит)старые программы под Windowsчерез стек ([esp+4]…)eaxret

ARM32 (ARMv7, Thumb)старые телефоны, микроконтроллерыr0–r3, дальше стекr0bx lr / pop {pc}

        
MIPSроутеры, IoT, старые приставки$a0–$a3$v0jr $ra (+ delay slot)

Порядок байтов (endianness)

    
Число 0x12345678 в памяти можно хранить с младшего байта (little-endian: x86, почти всегда ARM) или со старшего (big-endian: часть MIPS, PowerPC, сетевые протоколы). Если в hex-редакторе число «перевёрнуто» — это оно.

    

      
      

      

      

        
Little-endian (x86, ARM)

        
Big-endian (сеть, PowerPC)

      

      
Синим подсвечен младший байт. Адрес в памяти растёт слева направо.

    

  







  

    
03 · Неизвестный файл

    
Что это за файл и под какой процессор?

    

      
Первый вопрос с любым бинарником: формат, разрядность, архитектура. Ответ записан в заголовке файла. В терминале это делает file имя, а здесь — прямо в браузере. Файл никуда не загружается, всё читается локально.

Выбери файл или пример — здесь появится разбор заголовка.

    

    
То же самое в терминале

    
file ./target                # формат, разрядность, архитектура, stripped или нет
readelf -h ./target          # заголовок ELF подробно (поле Machine)
xxd ./target | head        # сырые байты
strings -n 6 ./target | less # читаемые строки: сообщения, URL, пароли

  







  

    
04 · Процесс

    
Как реверсить незнакомую программу

    
Не надо читать всё подряд. Ищи зацепки и иди от них. Отмечай шаги — прогресс сохранится в браузере.

    

    

    
    
    
    ⚠️
    Частые ловушки новичка: верить декомпилятору на 100% (он ошибается в типах), пытаться понять каждую функцию (90% — библиотечный код), забывать переименовывать (через час всё снова FUN_…).
    
  
    

    



    
  
    
    
    05 · Android
    
    
    Termux → proot Debian → Ghidra
    
    
    
      
    Termux — терминал Linux на Android без root. proot-distro ставит внутрь полноценный Debian (тоже без root). В Debian запускаем Ghidra, а окно выводим через Termux:X11.
    
    
    

    
    
      
    Минимум
    Телефон
    ARM64 (aarch64), Android 8+, от 6 ГБ RAM, 6–8 ГБ свободного места.
    
      
    Желательно
    Удобство
    Bluetooth-клавиатура и мышь, или планшет. Ghidra рассчитана на большой экран.
    
      
    Проверка
    Архитектура
    В Termux: uname -m → должно быть aarch64.
    
    
    

    
    ❗
    
      
    Главный нюанс: в официальных релизах Ghidra нет нативных компонентов для Linux ARM64 (только Windows и Linux x86-64). Без них не работает декомпилятор, самое ценное. Их нужно один раз собрать на телефоне — это шаг 7. Ghidra официально поддерживает Linux ARM64 с собранными пользователем нативными модулями.
    
    
    

    
    
      Termuxобычный Termux
      Debianвнутри proot Debian
      Телефоннастройки Android
    
    

    
      
      
    1. 
        
      Поставь Termux из правильного места Телефон
      
        
      Бери Termux с F-Droid или с GitHub. Версия из Google Play долго была устаревшей и ограниченной. Плюс поставь приложение Termux:X11 (termux-x11-universal-debug.apk или arm64-v8a).
      
        
      Не смешивай источники: Termux и его плагины должны быть из одного источника, иначе подписи не совпадут.
      
      
      2. 
      
    2. 
        
      Отключи убийцу фоновых процессов Телефон
      
        
      С Android 12 система убивает «лишние» дочерние процессы. Тяжёлая сборка или Ghidra внезапно падают с [Process completed (signal 9)].
      
        
        
          
      • Android 14+: Настройки → Для разработчиков → «Отключить ограничения дочерних процессов» (Disable child process restrictions).
        • 
          
      • Android 12–13: с компьютера через ADB:
        • 
        
      
        
      adb shell "/system/bin/device_config set_sync_disabled_for_tests persistent"
adb shell "/system/bin/device_config put activity_manager max_phantom_processes 2147483647"
      
        
      Ещё: отключи оптимизацию батареи для Termux и держи wake lock (в уведомлении Termux → Acquire wakelock).
      
      
      3. 
      
    3. 
        
      Обнови Termux и поставь proot-distro Termux
      
        
      pkg update && pkg upgrade -y
pkg install -y proot-distro x11-repo
pkg install -y termux-x11-nightly
termux-setup-storage   # доступ к /sdcard (по желанию)
      
      
      4. 
      
    4. 
        
      Установи Debian и зайди в него Termux
      
        
      proot-distro install debian
proot-distro login debian --shared-tmp
      
        
      --shared-tmp пробрасывает /tmp Termux внутрь — через него Debian рисует окна в Termux:X11. Выйти из Debian: exit.
      
      
      5. 
      
    5. 
        
      Поставь Java, сборщики и лёгкий рабочий стол Debian
      
        
      apt update && apt upgrade -y
apt install -y openjdk-21-jdk build-essential unzip wget curl git python3 \
               xfce4 dbus-x11 binutils file gdb
java -version
      
        
      XFCE можно заменить на что-то легче (openbox), но с XFCE проще.
      
      
      6. 
      
    6. 
        
      Скачай Ghidra и проверь нужную Java Debian
      
        
      cd ~
URL=$(curl -s https://api.github.com/repos/NationalSecurityAgency/ghidra/releases/latest \
      | grep -o 'https://[^"]*_PUBLIC_[^"]*\.zip' | head -1)
echo "$URL"
wget -O ghidra.zip "$URL" && unzip -q ghidra.zip && rm ghidra.zip
cd ~/ghidra_*_PUBLIC
grep java.min Ghidra/application.properties   # какая минимальная Java
      
        
      ☕
      Ghidra 12.0/12.1 требует JDK 21, а в документации ветки 12.2 уже JDK 25. Если java.min больше, чем показал java -version, поставь новее: apt install openjdk-25-jdk (если есть в репозитории) или скачай Temurin для aarch64 Linux с adoptium.net и пропиши JAVA_HOME.
      
      
      7. 
      
    7. 
        
      Собери нативные модули (декомпилятор) Debian
      
        
      cd ~/ghidra_*_PUBLIC/support/gradle
./gradlew buildNatives     # нужен интернет: wrapper скачает Gradle
      
        
      Идёт долго (десятки минут), телефон греется. Держи Termux на экране и на зарядке. В итоге в модулях появятся папки build/os/linux_arm_64/, и Ghidra будет брать бинарники оттуда.
      
        
      Сборка упала — что проверить
      
          
        
            
      • signal 9 / процесс исчез — вернись к шагу 2 и закрой другие приложения.
        • 
            
      • Не хватает памяти — закрой всё, перезапусти Termux, запусти сборку заново (готовое не пересобирается).
        • 
            
      • Не находит компилятор — проверь gcc --version и make --version; на старых версиях Ghidra помогала установка clang.
        • 
            
      • Ошибка версии Gradle/Java — нужна Java не ниже java.min из шага 6.
        • 
          
      
        
      
      
      8. 
      
    8. 
        
      Дай Ghidra памяти, но не всю Debian
      
        
      В скрипте ghidraRun есть строка MAXMEM — это предел памяти для Java. Правило: не больше половины RAM телефона, иначе Android убьёт Termux. На 8 ГБ ставь MAXMEM=3G.
      
        
      nano ~/ghidra_*_PUBLIC/ghidraRun   # MAXMEM=3G
      
      
      9. 
      
    9. 
        
      Запусти рабочий стол Termux
      
        
      Выйди из Debian (exit) и создай скрипт запуска:
      
        
      cat > ~/re.sh <<'X'
termux-x11 :0 >/dev/null 2>&1 &
sleep 3
proot-distro login debian --shared-tmp -- bash -c \
  "export DISPLAY=:0; dbus-launch --exit-with-session startxfce4"
X
chmod +x ~/re.sh && ~/re.sh
      
        
      Открой приложение Termux:X11 — там рабочий стол XFCE.
      
      
      10. 
      
    10. 
        
      Запусти Ghidra Debian
      
        
      В XFCE открой терминал:
      
        
      ~/ghidra_*_PUBLIC/ghidraRun
      
        
      Мелкий интерфейс? Edit → Tool Options → Theme → шрифт крупнее. Или в настройках Termux:X11 уменьши разрешение (Display resolution mode → scaled).
      
      
      11. 
    
    

    
    Без графики: headless-режим
    
    
    Если GUI тормозит, Ghidra умеет анализировать из командной строки. Проект потом можно открыть на ПК.
    
    
    mkdir -p ~/projects
~/ghidra_*_PUBLIC/support/analyzeHeadless ~/projects MyProj \
    -import ~/target.bin -overwrite
    

    
    Нюансы, о которые спотыкаются
    
    
    proot — это не настоящий Linux и не виртуалка
    proot подменяет системные вызовы через ptrace. Поэтому всё медленнее, нет systemd, а отладчики (gdb, strace) внутри proot часто работают нестабильно — им самим нужен ptrace. Для отладки ARM-бинарников удобнее ставить gdb прямо в Termux (pkg install gdb).
    
    
    Где хранить файлы
    Держи Ghidra и проекты в домашней папке Debian, а не на /sdcard: внешняя память не поддерживает права и симлинки Linux. Передать файл в Debian: положи в Termux ~/ и скопируй, или запускай Debian с --shared-home. Из Termux: proot-distro copy.
    
    
    Запуск x86-программ на телефоне
    ARM64-телефон не исполняет x86-код напрямую. Анализировать статически x86-файлы в Ghidra можно (ей не важно, под какой CPU файл). А запускать для динамики нужно эмулятором qemu-user (apt install qemu-user) — медленно, но работает для простых Linux-бинарников.
    
    
    Лёгкие альтернативы Ghidra прямо в Termux
      
      
    • pkg install radare2 — консольный дизассемблер, летает даже на слабом телефоне.
      • 
      
    • pkg install binutils file — readelf, objdump, strings, file.
      • 
      
    • jadx (релиз с GitHub, нужна Java) — для APK. Для Android-приложений это первый инструмент, а не Ghidra.
      • 
    
    
    
    Сбросить всё и начать заново
    proot-distro reset debian    # переустановить с нуля
proot-distro remove debian   # удалить совсем

    07 · Практика
    
    
    Мини-крякми: найди пароль
    
    
    Это вывод декомпилятора Ghidra из выдуманной программы. Функцию уже переименовали. Пойми логику и найди пароль. Всё, что нужно, есть в коде.
    
    
    int check_password(char *input)
{
  byte key[6] = { 0x25, 0x2a, 0x2b, 0x26, 0x30, 0x23 };
  int i;

  if (strlen(input) != 6) return 0;
  for (i = 0; i < 6; i++) {
    if ((input[i] ^ 0x42) != key[i]) return 0;
  }
  return 1;
}
    
    
    
      
    
        
        
    
        
    
        
    
          
    Подсказка 1
    Символ подходит, если input[i] XOR 0x42 == key[i]. XOR обратим: a ^ b ^ b = a.
    
          
    Подсказка 2
    Значит input[i] = key[i] ^ 0x42. Посчитай для каждого байта в калькуляторе справа и переведи в ASCII.
    
        
    
      
    
      
    
        
    XOR-калькулятор
    
        
    Байты через пробел или запятую, ключ — один байт.
